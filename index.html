02
02 What it checks Five monitors in v0.1.0. All read-only. None needs admin rights.

Five things that go wrong on a Mac, checked every few minutes.

These are not exotic attacks. They are the ordinary ways a Mac ends up exposed: a protection switched off and forgotten, a program that quietly starts at every login, an installer that Gatekeeper would have refused, a key anyone can copy.

postureFileVault · firewall · Gatekeeper · SIP · updates
The five protections macOS ships with, and whether each one is on. Turning them on needs your password, so xguard shows the exact steps and never runs them.
persistenceLaunchAgents · LaunchDaemons
Programs that start by themselves. This is how most Mac malware survives a restart. Flagged when a program is unsigned, missing, hidden, runs from a temporary folder, runs an inline shell command, or appeared since the last scan.
networklistening sockets
Your programs accepting connections from the whole network, not just from this Mac. Flagged when the program is unsigned or started listening since the last scan.
downloadslast 30 days
Installers, apps, disk images and scripts in your Downloads folder. Each one is checked against Gatekeeper’s own verdict, and flagged if it lost the quarantine flag that makes macOS check it when opened.
ssh~/.ssh
Private keys that other users on the Mac can read, and keys without a passphrase, which anyone who copies the file can use.

The first scan records what is already there and reports only what looks wrong on its own. After that, anything new stays reported until you review it.

03
03 How it works A scan takes about a second. The default interval is ten minutes.

It watches on its own. It never acts on its own.

I

Baseline

On the first run, each monitor records what is already on the Mac: the startup items, the programs listening, the state of each protection. Only things that are wrong on their own are reported, so the first list is short and worth reading.

Reads
launch configurations, code signatures, Gatekeeper verdicts, your own sockets, file permissions
Writes
one SQLite file in ~/.xguard
Needs
no admin rights, no network
II

Watch

Every ten minutes the checks run again. A new startup item, a program that just opened a port, a downloaded installer that Gatekeeper rejects: each becomes a finding with a severity, the evidence, and the actions available. Serious ones also arrive as a macOS notification. A finding that disappears is marked resolved; one you dismiss stays dismissed.

Runs
in the background, as a launch agent you install with one command and remove with another
Alerts
Notification Center, for medium severity and above
III

Decide

xguard show explains a finding and lists what you can do. If you give xguard an Anthropic API key, Claude reads the finding and writes the explanation in plain language, in your language, and suggests at most one of the listed actions. You approve, dismiss, or do nothing. Approved actions are logged and, where possible, reversible with xguard restore.

Claude
optional · sees one finding at a time · evidence is passed as untrusted data · cannot run anything
Actions
quarantine a file or startup item (reversible) · fix key permissions (reversible) · quit one of your processes
Admin
anything that needs your password is shown as instructions, never run

Nothing changes until you say so.

04
04 Trust The code is public. Read it before you run it.

What xguard can do, and what it can’t.

Can

  • Read launch configurations, code signatures, Gatekeeper verdicts, your listening sockets and the permissions of your SSH keys.
  • Keep findings, baselines and an audit log in one SQLite file in your home folder.
  • Send a macOS notification when a serious finding appears.
  • Move a file or a startup item you own into its quarantine, and move it back.
  • Ask Claude to explain one finding, if and only if you provide a key.

Cannot

  • Run anything as administrator. There is no code path that asks for your password.
  • Change anything before you approve it. Not a file, not a setting, not a process.
  • Send your files anywhere. Without a key, it makes no network requests at all.
  • Read the contents of your documents. It reads metadata, signatures and permissions.
  • Let Claude act. The model returns text; xguard discards any suggested action that the finding does not already list.
DATA
Everything xguard knows lives in ~/.xguard: a SQLite database, the audit log and the quarantine folder. Delete the folder and xguard forgets everything. There is no account, no telemetry and no update check.
CLAUDE
When you set an Anthropic API key, each new finding is sent once, as a single JSON object, to the Claude API under your own account. File names, labels and arguments can be written by an attacker, so the prompt treats them as untrusted data, and the reply is validated before it is shown. Roughly a cent per finding, billed by Anthropic to you, never to xguard.
ADMIN
Turning on FileVault or the firewall, stopping a system-wide daemon, re-enabling SIP: these need your password, so xguard prints the exact steps and leaves them to you. A security tool that asks for your password is a security tool you have to trust completely. This one doesn’t ask.
LIMITS
xguard is not an antivirus and does not scan file contents for malware signatures. Without admin rights, the network check sees only your own processes. It has no threat-intelligence feed yet: its judgments come from signatures, locations and change over time.

Every command

Run every check once.
xguard findings
List what is open. Add --all to include what you dismissed or fixed.
xguard show <id>
The finding, the evidence, the explanation, and the actions you can approve.
xguard approve <id> <action>
Let xguard act. It asks for confirmation first.

Everything xguard detected and did, with timestamps.

Keep scanning in the foreground. Ctrl+C to stop.

Run in the background at login. uninstall-agent removes it.

Last scan, open findings, whether Claude explanations and the background agent are on.
07
07 Questions

Questions a careful person asks.

Does it need my password or admin rights?

No. Every check runs as you. Fixes that need admin rights, like turning on FileVault, are printed as steps for you to run.

Does it send my data anywhere?

Without an Anthropic key, nothing: xguard makes no network requests. With a key, each new finding is sent once to the Claude API under your account, as a small JSON object with the file name, the label, the program path and the arguments. Never the contents of your files.

Is it an antivirus?

No. It does not scan file contents for malware signatures. It watches the places where things go wrong on a Mac, notices change, and tells you. Keep macOS’s own protections on; xguard will tell you if they are off.

What if it is wrong about something?

Dismiss it. The finding stays dismissed unless the thing it describes changes. If an action was already approved, xguard restore puts the file or startup item back exactly where it was.

Why Claude, and why optional?

The checks are code, and they decide what is reported. Claude only writes the explanation and suggests one of the actions already on the finding, so the list is just as complete without it. It is optional because it costs you money and sends a small amount of data off your Mac, and that should be your call.

How do I remove it?

Run xguard uninstall-agent if you installed the background agent, then uv tool uninstall xguard. Delete ~/.xguard to remove the findings, the log and the quarantine. Nothing else was touched.

Which Macs?

Apple silicon and Intel, macOS 13 or later. Linux and Windows are not supported: the checks use macOS tools like codesign, spctl and launchctl.
